# Mic-watcher: точная привязка к приложению + постоянный per-app игнор

Дата: 2026-06-03
Запросчик: Geo
Статус: дизайн утверждён, реализация

## Проблема

Всплывающее окно «Начать запись встречи?» (правый верх) раздражает: появляется
не на том приложении. Причина в коде: система сообщает только «микрофон включился»
(уровень устройства, `kAudioDevicePropertyDeviceIsRunningSomewhere` - без имени
процесса), и watcher **угадывает** приложение - берёт первое запущенное из whitelist.
Если открыт Telegram, а микрофон включил VoiceInk - окно винит Telegram.

Плюс: «Игнорировать» сейчас = только кулдаун (`mark_ignored` пишет в `last_shown`),
постоянного игнора нет; настройки не сохраняются на диск (после перезапуска сброс).

## Как делает конкурент (Hyprnote / переименован в anarlog)

`crates/detect/src/list/macos.rs`: per-process API CoreAudio (macOS 14.2+):
- `kAudioHardwarePropertyProcessObjectList` - список аудио-процессов;
- `kAudioProcessPropertyIsRunningInput` - кто из них активно пишет ВХОД (микрофон);
- bundle id/name процесса (через `kAudioProcessPropertyBundleID` / PID + NSRunningApplication).

Браузер при этом виден как один процесс (Chrome/Arc) - различить Meet/Zoom-web внутри
нельзя (Hyprnote тоже не умеет). Решение Geo: **делаем как Hyprnote** - браузер = одно
приложение, тонкой настройки по вкладкам нет.

Константы уже доступны в наших биндингах `coreaudio-sys` 0.2.17 (SDK macOS 14.2+).

## Дизайн

### Детекция (Rust, mic_watcher.rs)
- Новая `apps_using_microphone() -> Vec<MeetingApp>` через per-process API
  (ProcessObjectList → IsRunningInput → BundleID). Возвращает РЕАЛЬНЫЕ приложения,
  держащие микрофон.
- Watcher: вместо «угадывания» сравнивает множество mic-приложений между тиками.
  На НОВОЕ приложение, начавшее использовать микрофон:
  - в blacklist (игнор) → пропустить;
  - в whitelist (митинг-приложение) → показать окно, привязанное к ЭТОМУ приложению;
  - иначе (неизвестное, напр. VoiceInk) → не показывать (без шума).
- macOS < 14.2 или per-process пусто → запасной режим (текущая device-level логика).
- Windows: без изменений (фича macOS-only).

### Постоянный игнор + персист
- `MicWatcherSettings.blacklist`: `Vec<String>` → `Vec<MeetingApp>` (bundle_id + name),
  чтобы в настройках показывать имя.
- Настройки сохраняются на диск (JSON в data_dir, рядом с insapp-credentials.json):
  load при старте, save при изменении. Игнор переживает перезапуск.
- `mark_ignored(bundle_id, name)` → добавить в blacklist + save (а не кулдаун).
- Новая команда `mic_watcher_unignore(bundle_id)` → убрать из blacklist + save.

### UI
- Окно-попап: кнопка «Игнорировать» → добавляет это приложение в игнор + тост
  «<App> добавлено в игнорируемые. Изменить - в Настройках».
- Настройки: новый раздел «Игнорируемые приложения» - список (имя приложения),
  у каждого кнопка «Вернуть» (убрать из игнора → снова будет предлагать запись).

## Вне рамок (YAGNI)
- Различение сайтов внутри браузера по вкладке (Geo выбрал «как Hyprnote»).
- Календарная интеграция для проактивных напоминаний.

## Критерии приёмки
1. VoiceInk включает микрофон при открытом Telegram → окно НЕ появляется (или не винит Telegram).
2. Митинг-приложение из whitelist → окно с правильным именем.
3. «Игнорировать» → приложение исчезает из триггеров навсегда (и после перезапуска).
4. В Настройках виден раздел игнорируемых, «Вернуть» возвращает приложение.
